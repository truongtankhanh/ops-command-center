# Documentation rules

## ADRs (`docs/adr/`)

- File `NNNN-kebab-title.md`, next free number; title `# ADR-NNNN: <decision as a sentence>`.
- Header: `- **Status:**` (`Accepted`, optionally with a date or `amended by [ADR-nnnn]`), `- **Date:**`, and
  `- **Context documents:**` when it builds on a design doc or another ADR.
- Sections: Context, Options, Decision, Consequences (and "Decided before acceptance" when it applies). Record the
  alternatives considered and the constraint that forced the choice.
- Do not rewrite an accepted ADR's decision; supersede or amend it and link both ways.
- Adding or changing an ADR also updates the ADR table in `README.md` and the Decisions table in
  `docs/architecture.md` (§9). Note that §9 does not list every ADR yet; do not "fix" unrelated rows in the same PR.

## API reference (`docs/api/`)

- One file per module plus `README.md` (conventions that apply to every endpoint). Each endpoint has a `Source` line
  pointing at the code. `openapi.json` is generated from the code by the API-docs pipeline, not written by hand.
- A route, DTO, status code, permission or rate-limit change updates the module file, the conventions table in
  `docs/api/README.md` if it is cross-cutting, and `openapi.json`.

## Generated content

- `docs/design/tokens.md` between the `contrast:start/end` markers is generated by
  `pnpm --filter @occ/console tokens:contrast`; edit around the markers only.
- Run `pnpm format:check` (Prettier covers Markdown) before committing docs.

## What is tracked

- Tracked: `README.md`, `docs/adr`, `docs/api`, `docs/architecture.md`, `docs/roadmap.md`, `docs/design`
  (including `docs/design/v2/brief.md`).
- Working directories under `docs/` (plan, audit, test, setup, performance, context and a few design/planning
  notes) are git-excluded per developer. Never link to them from a tracked document.
- Write English. Keep `README.md` and `docs/` descriptions of the system as built; plans and status belong in
  tickets, not in docs.
